# Samples

Small, tracked inputs and reference projects that the docs and CI point at. Each row links to the sample's own README for details; run commands are relative to the repository root. Ashlar packages are **not yet published to nuget.org**, so every runnable sample here works from a checkout (`ProjectReference` or a local folder feed), never from a package install.

| Sample | What it shows | Run command | Prerequisites |
|--------|---------------|-------------|---------------|
| [`hello-brick/`](hello-brick/README.md) | The complete code-authored brick reference (`HelloBrick : Brick` + xUnit smoke test) via `ProjectReference` to `src/Ashlar.Core.Domain`. **Start here** for brick authoring (`docs/AuthoringBricks.md`). | `dotnet test samples/hello-brick/HelloBrick.Tests/HelloBrick.Tests.csproj` | .NET SDK (`global.json`) |
| [`templates/brick/`](templates/brick/README.md) | The `__BrickName__` token template that `ashlar new brick <Name>` copies (embedded in the CLI). Generated project references the `Ashlar.Authoring` package, so it needs a local feed or a `ProjectReference` swap. | `dotnet run --project application/src/Ashlar.CLI -- new brick Hello --output /tmp/hello-brick --ashlar-version 9.9.9-local` (restore recipe: `docs/AuthoringBricks.md`, "Restoring Ashlar.Authoring") | .NET SDK; local feed from `scripts/verify-standalone-brick-authoring.sh` to restore |
| [`certified-brick-reuse/`](certified-brick-reuse/README.md) | Project A certifies `DamageResolverBrick` (content-bound, HMAC-signed record); Project B verifies signature + content hash and runs it untouched, referencing no gate or generator. | `bash scripts/run-cert-gate.sh` (CI proof); by hand: `bash scripts/pack-certified-brick-reuse.sh` then restore/run `ProjectB` against `artifacts/certified-brick-feed/NuGet.Config` | .NET SDK; Docker not required |
| [`autonomy-objectives/`](autonomy-objectives/README.md) | Four tracked autonomy objectives (objective `.md` + witness `.json` written first + recorded model proposals) for the trust loop; the `.proposal.json` files are real ollama output kept verbatim, defects included. | `cp samples/autonomy-objectives/door-lock-transition.* .ashlar/runtime-studio/objectives/pending/` then run a host composed with `AddAshlarAutonomy` + `AddAshlarAutonomyLoop` (see its README) | .NET SDK; a container engine (candidates build/run in an attested session); ollama for live proposals |
| [`approval-workflow/`](approval-workflow/README.md) | Minimal AWS Step Functions ASL (`sample-approval.asl.json`) using the `waitForTaskToken` callback pattern so a GitHub check can approve a step. | Deploy `sample-approval.asl.json` as a Step Functions state machine (no local runner) | AWS account, Lambda with a GitHub App token / PAT in Secrets Manager |
| [`aws-sns-ashlar-lambda/`](aws-sns-ashlar-lambda/README.md) | Node.js 20 Lambda + SAM template that reshapes an SNS-triggered payload into the SNS HTTP subscription shape so `Ashlar.Ingress.AwsSns` signature verification runs unchanged. | `sam deploy --guided --parameter-overrides AshlarSmsUrl=https://your-host.example.com/api/ingress/sms/sns` (from `samples/aws-sns-ashlar-lambda/`) | AWS account, SAM CLI, a reachable Ashlar.API SMS ingress endpoint |

`Directory.Build.props` in this folder adds the `DomainBrick` global-using alias (`src/Ashlar.Compat/GlobalUsings.DomainBrick.cs`) to `HelloBrick` and `Ashlar.Certified.DamageResolver` only.

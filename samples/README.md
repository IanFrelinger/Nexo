# Samples

Small, tracked inputs and reference projects that the docs and CI point at. Each row links to the sample's own README for details; run commands are relative to the repository root. Every runnable sample here works from a checkout (`ProjectReference` or a local folder feed) so it stays in step with `src/`; `Ashlar.*` is also **on nuget.org at `0.1.1`** if you would rather consume it as packages (`docs/ConsumingFromNuGet.md`).

| Sample | What it shows | Run command | Prerequisites |
|--------|---------------|-------------|---------------|
| [`hello-brick/`](hello-brick/README.md) | The complete code-authored brick reference (`HelloBrick : Brick` + xUnit smoke test) and the smallest brick the certification gate admits: one file, one `PackageReference` to `Ashlar.Brick.Contracts 0.1.1`, a witness beside it. **Start here** for brick authoring (`docs/AuthoringBricks.md`). | `dotnet test samples/hello-brick/HelloBrick.Tests/HelloBrick.Tests.csproj`; certify: see `hello-brick/README.md` | .NET SDK (`global.json`); nuget.org for the one package |
| [`templates/brick/`](templates/brick/README.md) | The `__BrickName__` token template that `ashlar new brick <Name>` copies (embedded in the CLI). The generated brick project references the `Ashlar.Authoring` package — `--ashlar-version 0.1.1` restores from plain nuget.org; only a version you packed yourself needs a local feed. The template as tracked here certifies exactly as scaffolded under the gate at this line (`BrickCertificationProjectLoaderReferenceTests`, since `0.1.2`); the template embedded in the **`0.1.1` CLI** is the older one and is rejected by this gate. | `dotnet run --project application/src/Ashlar.CLI -- new brick Hello --output /tmp/hello-brick --ashlar-version 0.1.1` (pre-release feed recipe: `docs/AuthoringBricks.md`, "Restoring Ashlar.Authoring") | .NET SDK; nuget.org for `Ashlar.Authoring` (or a local feed from `scripts/verify-standalone-brick-authoring.sh` for a `9.9.9-local` build) |
| [`certified-brick-reuse/`](certified-brick-reuse/README.md) | Project A certifies `DamageResolverBrick` (content-bound, HMAC-signed record; the mutant count and kill list are whatever `Ashlar.Certified.DamageResolver/certification-record.json` says — it is regenerated whenever the mutation catalog changes, so this page does not repeat the numbers); Project B verifies signature + content hash and runs it untouched, referencing no gate or generator. | `bash scripts/run-cert-gate.sh` (CI proof); by hand: `bash scripts/pack-certified-brick-reuse.sh` then restore/run `ProjectB` against `artifacts/certified-brick-feed/NuGet.Config` | .NET SDK; Docker not required |
| [`autonomy-objectives/`](autonomy-objectives/README.md) | Four tracked autonomy objectives (objective `.md` + witness `.json` written first + recorded model proposals) for the trust loop; the `.proposal.json` files are real ollama output kept verbatim, defects included. | `cp samples/autonomy-objectives/door-lock-transition.* .ashlar/runtime-studio/objectives/pending/` then run a host composed with `AddAshlarAutonomy` + `AddAshlarAutonomyLoop` (see its README) | .NET SDK; a container engine (candidates build/run in an attested session); ollama for live proposals |
| [`approval-workflow/`](approval-workflow/README.md) | Minimal AWS Step Functions ASL (`sample-approval.asl.json`) using the `waitForTaskToken` callback pattern so a GitHub check can approve a step. | Deploy `sample-approval.asl.json` as a Step Functions state machine (no local runner) | AWS account, Lambda with a GitHub App token / PAT in Secrets Manager |
| [`aws-sns-ashlar-lambda/`](aws-sns-ashlar-lambda/README.md) | Node.js 20 Lambda + SAM template that reshapes an SNS-triggered payload into the SNS HTTP subscription shape so `Ashlar.Ingress.AwsSns` signature verification runs unchanged. | `sam deploy --guided --parameter-overrides AshlarSmsUrl=https://your-host.example.com/api/ingress/sms/sns` (from `samples/aws-sns-ashlar-lambda/`) | AWS account, SAM CLI, a reachable Ashlar.API SMS ingress endpoint |

`Directory.Build.props` in this folder is deliberately empty: it shields `samples/` from the repository-root `Directory.Build.props`. It used to inject the `DomainBrick` alias file into `HelloBrick` and `Ashlar.Certified.DamageResolver` — a compile item from outside the brick directory, which the certification gate now refuses.
